# distillarium-content

**GitHub:** <https://github.com/doc9830/distillarium-content> (публичный:
OTA-клиент скачивает релизные файлы без токена) ·
[релизы](https://github.com/doc9830/distillarium-content/releases)

Контент приложения «Дистиллярий»: вики, справочники, рецепты, медиа.
Отдельный репозиторий — правка опечатки не требует новой сборки APK.
Приложение: <https://github.com/doc9830/distillarium-app>.

**Лицензия:** source available, см. [`LICENSE`](LICENSE). Лицензия на контент
пока не выбрана — открытый вопрос проекта.

## Что внутри

```
content/
  version.json        версия пакета, schemaVersion, minAppVersion, дата релиза
  wiki/**/*.md        статьи вики; путь = стабильный id (wiki/<id>.md)
  reference/*.json    справочные таблицы
  recipes/*.json      шаблоны рецептов
  calculators.json    каталог калькуляторов для ссылок `calc:`
  tree.json           дерево навигации: разделы, порядок и размещение статей
  media/**            картинки (WebP), только там, где без них непонятно
  redirects.json      старые адреса → стабильные id
tools/
  build-content.mjs   сборка пакета одной командой
  validate-content.mjs проверка готового пакета
  editor/             локальный веб-редактор контента (без зависимостей)
  lib/                разбор frontmatter, проверки, индекс поиска, zip
dist/                 результат сборки (в git не попадает)
```

**Стабильный id** — путь статьи без `wiki/` и `.md`, например
`processes/separate/fractional`. Он не меняется никогда. Переезд статьи —
запись в `redirects.json`: `{"articles/old-slug": "processes/new-id"}`.
При создании статьи в редакторе id указывать не нужно: он собирается из
заголовка транслитерацией (`articles/novaya-statya`), а при совпадении
получает суффикс `-2`, `-3`. Подставленный id остаётся редактируемым до
сохранения; через API явный `id` тоже можно передать.

## Сборка

Требуется Node.js 20+ и больше ничего (внешних зависимостей нет).

```bash
node tools/build-content.mjs
```

Одна команда собирает:

| Артефакт | Что это |
| --- | --- |
| `dist/content/` | распакованный пакет: `manifest.json`, `wiki/`, `search/index.json`, `redirects.json` |
| `dist/content-pack.zip` | архив пакета для загрузки приложением |
| `dist/manifest.json` | манифест релиза: версии, `packSize`, `packSha256`, `files[].sha256` |
| `dist/build-report.json` | отчёт сборки: число статей, ссылок, статей без источников |

Параметры версии по умолчанию берутся из `content/version.json`; флаги их
переопределяют. `released` — дата выпуска версии, а не дата запуска сборки:
один и тот же контент должен давать один и тот же sha256 в любой день.

```bash
node tools/build-content.mjs \
  --content-version 2026.11.1 \
  --min-app-version 0.1.0 \
  --released 2026-11-01
```

## Проверка

```bash
node tools/validate-content.mjs            # dist/content
node tools/validate-content.mjs <путь>     # любой распакованный пакет
```

Валидатор проверяет:

- манифест: версии, список файлов, размеры и `sha256` каждого файла;
- уникальность `id` и совпадение `id` с путём файла;
- обязательные поля `id`, `title`, `short`;
- все ссылки `[[…]]` (статьи, `calc:`, `ref:`, `recipe:`);
- `redirects.json`: цель существует, цепочек нет;
- медиа: локальные файлы на месте, внешние картинки запрещены;
- индекс поиска: совпадает с набором статей.

**Битая ссылка валит сборку.** Если сборка прошла — в пакете нет битых ссылок,
дублей id и расхождений хешей.

## Локальный редактор

Локальный веб-редактор для статей и JSON-данных. Это инструмент автора на
машине, а не сетевая админка: сервер слушает только `127.0.0.1`.

```bash
npm run editor                 # http://127.0.0.1:4173
npm run editor -- --port 4180
npm run editor -- --root /путь/к/distillarium-content
```

Что умеет:

- дерево статей слева: всегда видны разделы и «Без раздела», статьи можно
  перетаскивать между разделами и менять порядок прямо в списке;
- поиск и фильтры по разделам дерева и тегам (фильтр скрывает только статьи,
  структура дерева остаётся на месте);
- Markdown-редактор с безопасным живым предпросмотром, форматированием
  и оглавлением;
- вставку ссылок на статьи, калькуляторы, справочные таблицы и внешние адреса;
- конструктор дерева навигации: разделы и подразделы, перетаскивание статей,
  переименование, порядок и список «Без раздела». Одну статью можно разместить
  в нескольких разделах: включите «Показать использующиеся» и перетащите её ещё
  раз, не дублируя текст;
- кнопку «Разложить по категориям»: переносит старые категории в обычные
  разделы дерева, после чего их можно свободно перетаскивать;
- правку frontmatter: `title`, `short`, разделы дерева, теги, калькуляторы,
  источники. Выбранные в форме разделы применяются к `tree.json` при
  сохранении статьи; теги предлагаются из общего каталога по всем статьям.
  Категория остаётся в данных для совместимости, но навигацию задаёт только
  `tree.json`;
- создание статьи прямо в редакторе: заголовок вводится в форме, id
  подставляется из него и остаётся редактируемым до сохранения. Изменение
  технического id у существующей статьи создаёт запись в `redirects.json` и
  обновляет `wikiId` в рецептах;
- удаление статьи с очисткой её размещений в дереве, ссылок `[[…]]` в других
  статьях и `wikiId` в шагах рецептов; при удалении можно указать статью для
  редиректа;
- загрузку картинок в `content/media/` (WebP, PNG, JPEG до 8 МБ);
- правку `reference/*.json`, `recipes/*.json`, `calculators.json`,
  `redirects.json`, `version.json`;
- проверку, сборку и публикацию: проверка → сборка → коммит → `git push`,
  при необходимости с тегом `content-*` для GitHub Actions.

Публикация требует настроенных `git user.name` и `git user.email` в
репозитории. Все записи атомарные; редактор не выполняет код из контента.
Сервер принимает изменения только с localhost и не заменяет собой Git:
источник правды остаётся в Markdown, JSON и истории коммитов.

Тесты редактора не зависят от сети и работают на временной копии:

```bash
npm run test:editor
```

## Формат манифеста

Внутри `dist/content/manifest.json`:

```json
{
  "contentVersion": "2026.10.4",
  "schemaVersion": 1,
  "minAppVersion": "0.1.0",
  "released": "2026-10-18",
  "files": [{ "path": "wiki/...md", "sha256": "…", "size": 4210 }],
  "searchIndex": "search/index.json",
  "searchIndexSha256": "…",
  "redirects": "redirects.json"
}
```

В релизном `dist/manifest.json` дополнительно есть `packSize` и `packSha256` —
хеш и размер `content-pack.zip`. Внутри архива этих двух полей нет: иначе
получился бы циклический хеш. Приложение берёт их из скачанного манифеста
и записывает в `installed.json`.

Правила версий:

- `contentVersion` — `год.месяц.порядковый`, сравнивается как версия;
- `schemaVersion` — версия схемы контента, текущая **1**;
- `minAppVersion` — минимальная версия приложения, понимающая пакет.

## Правила для автора

1. Одна статья — одна задача. Ответ — в первых двух строках.
2. `id` не меняется. Переезд — только через `redirects.json`.
3. Новые статьи без источника не пишем. Если цифру подтвердить нельзя —
   диапазон и пометка «ориентир, проверяйте на своём аппарате».
4. Импортированные статьи с `sources: []` — признанный долг, а не повод
   удалять статью или ломать сборку.
5. Контент не выполняет код: только Markdown и JSON.
6. `wiki/` — единственный источник статей. `INDEX.md` и служебные файлы
   в пакет не попадают.

## CI

`.github/workflows/content.yml` на каждый пуш и pull request собирает пакет,
проверяет архив и падает при любой ошибке валидации. На тег `content-*`
публикует `content-pack.zip` и `manifest.json` в релиз, обновляет
`content-latest`. Проверено на GitHub: `main` и тег `content-2026.10.8` зелёные;
релиз содержит `content-pack.zip` (sha256 `a7471b73…`) и `manifest.json`.

Репозиторий публичный, поэтому приложение скачивает эти файлы по прямым
ссылкам без токена. Проверка 19.10.2026: `content-latest` отдаёт
`manifest.json` и `content-pack.zip` без авторизации, sha256 архива
`a7471b7311b572c8ee1659cc2087bcba37c1e16fb744a792712acb694548ac51`
совпадает с `packSha256` в манифесте.
