# distillarium-content

Контент приложения «Дистиллярий»: вики, справочники, рецепты, медиа.
Отдельный репозиторий — правка опечатки не требует новой сборки APK.

**Лицензия:** source available, см. [`LICENSE`](LICENSE). Лицензия на контент
пока не выбрана — открытый вопрос проекта.

---

## Что внутри

```
content/
  version.json        версия пакета, schemaVersion, minAppVersion, дата релиза
  wiki/**/*.md        статьи вики; путь = стабильный id (wiki/<id>.md)
  reference/*.json    справочные таблицы
  recipes/*.json      шаблоны рецептов
  calculators.json    каталог калькуляторов для ссылок `calc:`
  media/**            картинки (WebP), только там, где без них непонятно
  redirects.json      старые адреса → стабильные id
tools/
  build-content.mjs   сборка пакета одной командой
  validate-content.mjs проверка готового пакета
  lib/                разбор frontmatter, проверки, индекс поиска, zip
dist/                 результат сборки (в git не попадает)
```

**Стабильный id** — путь статьи без `wiki/` и `.md`, например
`processes/separate/fractional`. Он не меняется никогда. Переезд статьи —
запись в `redirects.json`: `{"/articles/old-slug": "processes/new-id"}`.

## Сборка

Требуется Node.js 20+ и больше ничего (внешних зависимостей нет).

```bash
node tools/build-content.mjs
```

Одна команда собирает:

| Артефакт | Что это |
| --- | --- |
| `dist/content/` | распакованный пакет: `manifest.json`, `wiki/`, `search/index.json`, `redirects.json` |
| `dist/content-pack.zip` | архив пакета для загрузки приложением |
| `dist/manifest.json` | манифест релиза: версии, `packSize`, `packSha256`, `files[].sha256` |
| `dist/build-report.json` | отчёт сборки: число статей, ссылок, статей без источников |

Параметры версии по умолчанию берутся из `content/version.json`; флаги их
переопределяют. `released` — дата выпуска версии, а не дата запуска сборки:
один и тот же контент должен давать один и тот же sha256 в любой день.

```bash
node tools/build-content.mjs \
  --content-version 2026.11.1 \
  --min-app-version 0.1.0 \
  --released 2026-11-01
```

## Проверка

```bash
node tools/validate-content.mjs            # dist/content
node tools/validate-content.mjs <путь>     # любой распакованный пакет
```

Валидатор проверяет:

- манифест: версии, список файлов, размеры и `sha256` каждого файла;
- уникальность `id` и совпадение `id` с путём файла;
- обязательные поля `id`, `title`, `short`;
- все ссылки `[[…]]` (статьи, `calc:`, `ref:`, `recipe:`);
- `redirects.json`: цель существует, цепочек нет;
- медиа: локальные файлы на месте, внешние картинки запрещены;
- индекс поиска: совпадает с набором статей.

**Битая ссылка валит сборку.** Если сборка прошла — в пакете нет битых ссылок,
дублей id и расхождений хешей.

## Формат манифеста

Внутри `dist/content/manifest.json`:

```json
{
  "contentVersion": "2026.10.3",
  "schemaVersion": 1,
  "minAppVersion": "0.1.0",
  "released": "2026-10-18",
  "files": [{ "path": "wiki/...md", "sha256": "…", "size": 4210 }],
  "searchIndex": "search/index.json",
  "searchIndexSha256": "…",
  "redirects": "redirects.json"
}
```

В релизном `dist/manifest.json` дополнительно есть `packSize` и `packSha256` —
хеш и размер `content-pack.zip`. Внутри архива этих двух полей нет: иначе
получился бы циклический хеш. Приложение берёт их из скачанного манифеста
и записывает в `installed.json`.

Правила версий:

- `contentVersion` — `год.месяц.порядковый`, сравнивается как версия;
- `schemaVersion` — версия схемы контента, текущая **1**;
- `minAppVersion` — минимальная версия приложения, понимающая пакет.

## Правила для автора

1. Одна статья — одна задача. Ответ — в первых двух строках.
2. `id` не меняется. Переезд — только через `redirects.json`.
3. Новые статьи без источника не пишем. Если цифру подтвердить нельзя —
   диапазон и пометка «ориентир, проверяйте на своём аппарате».
4. Импортированные статьи с `sources: []` — признанный долг, а не повод
   удалять статью или ломать сборку.
5. Контент не выполняет код: только Markdown и JSON.
6. `wiki/` — единственный источник статей. `INDEX.md` и служебные файлы
   в пакет не попадают.

## CI

`.github/workflows/content.yml` на каждый пуш и pull request собирает пакет,
проверяет архив и падает при любой ошибке валидации. На тег `content-*`
публикует `content-pack.zip` и `manifest.json` в релиз, обновляет
`content-latest`.
